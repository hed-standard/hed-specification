# Release 4.0.0 (unreleased)

Specification 4.0.0 is a major revision written against HED standard schema `8.5.0`. It makes the reserved tags (`Definition`, `Def`, `Def-expand`, `Onset`, `Offset`, `Inset`, `Delay`, `Duration`, `Event-context`) a single table of group rules that applies to every standard schema >= `8.0.0`, and publishes that table, the character sets of section 2.2, and the plurals of the unit names as machine-readable JSON files that validators load. It sets strict rules for tabular files and sidecars (column names, padded values, sidecar keys, nothing trimmed), makes units case-sensitive with per-component rules for compound units, defines how library schemas combine in merge groups, and adds the JSON and TSV schema formats with the Sources, Prefixes and External annotations sections. Many annotations that passed under 3.3.0 are now errors; read the upgrade notes first. The repository no longer holds schemas, tests or PDFs of the specification; release PDFs are published with the documentation.

## Upgrade notes for implementers

These changes alter what is valid or how validators must report it.

- **Reserved tags (3.2.8).** The group rules of the reserved tags are one generated table, read from `docs/source/_static/reserved_tags.json`, and apply in every standard schema >= `8.0.0`, including `8.0.0` and `8.1.0`, which have no `reserved` attribute. A reserved tag MUST NOT be extended (`Onset/Blah`, TAG_EXTENSION_INVALID c); `Onset/#` may be reported as TAG_EXTENSION_INVALID or PLACEHOLDER_INVALID. `Delay` and `Duration` require a value (TAG_REQUIRES_CHILD b).
- **Versions of the machine-readable files (A.6.1).** `reserved_tags.json` carries `specificationVersion` and `fileVersion`, and `character_sets.json` and `unit_plurals.json` carry `specification_version` and `file_version`, each file in the case of its own keys. A validator MUST NOT apply a file whose file version major number it does not support.
- **`Delay` (3.2.8, 5.3.4).** `Delay` may share a top-level group with `Onset`, `Offset`, `Inset` or `Duration`; on its own it needs exactly one inner group. It may appear only in timeline tables (TEMPORAL_TAG_ERROR k, l, m).
- **Units of `Delay` and `Duration` (3.2.8.4).** The default unit is `s`. In a timeline table the unit must have a `conversionFactor`, so `month` and `year` are errors there (TEMPORAL_TAG_ERROR n); a descriptor table may use any unit with `Duration`. Under `8.0.0`, whose time units have no conversion factors, a value with no unit or in `s`, `second` or `seconds` is taken as is.
- **Definitions (3.2.8.1).** A definition without a placeholder MAY have no inner group again (3.1.0 required one). Only `#` may follow the definition name (DEFINITION_INVALID l). The contents may contain no structural reserved tag at any level (d) and no `unique` tag (j). A name defined twice with identical contents is accepted, even twice in one HED string: identical `Definition` groups are not a repeated expression (TAG_EXPRESSION_REPEATED). Only differing contents are DEFINITION_INVALID (i). An empty inner group (`(Definition/X, ())`) is TAG_EMPTY (c), not DEFINITION_INVALID (b), which is no longer used. Contents are compared under the case rule of 3.2.3, so contents that differ only in the case of a value are different. Definitions MUST NOT appear in the annotations of a tabular file.
- **Time in a timeline table (3.2.8.3, 3.2.10.4).** The rules for `Onset`, `Offset` and `Inset` use the time in the `onset` column, not the position of a row, so the rows need not be in time order; a table whose rows are out of time order is valid and gets a warning (ONSETS_UNORDERED). The rules apply to one table at a time. An `Onset` with no `Offset` is not an error: its event process does not end within the table and is ongoing at every later row, including the last. A row whose `onset` value is `n/a` has no time and MUST NOT contain `Onset`, `Offset`, `Inset` or `Delay` (TEMPORAL_TAG_ERROR o); it MAY contain `Duration`.
- **`Event-context` (3.2.8.5, 5.5).** The group holds no tags outside its inner groups (TAG_GROUP_ERROR d) and no `{column}` reference (TAG_GROUP_ERROR e). It is generated by tools, in the form `(Event-context, (entry, entry, ...))`, with one entry for each event process that started before the event marker and has not ended: the process's `Onset` or `Duration` group with that tag and any `Delay` removed. A process is not in the context of the marker at which it starts or ends; a process with no `Offset` is in the context of every later row, including the last. A row whose `onset` value is `n/a` neither gets nor contributes to a context. 5.5 has a worked example.
- **Tag extensions (3.2.5).** An extension term MUST contain only `name` characters and at least one letter (new rule 6), so `Item/Blech/3` and `Item/1-2` are TAG_EXTENSION_INVALID (b) while `Item/3D-printout` is valid; a letter may be any Unicode letter in standard schemas >= `8.3.0`. A `#` after an extension (`Item/Blech/#`) is PLACEHOLDER_INVALID (d) in every context. These apply to every standard schema >= `8.0.0`.
- **Tags (3.2.2, Appendix B).** Internal whitespace in a tag is TAG_INVALID (b), including a blank directly before or after a slash of the tag path or the slash that begins a value (`Label/ abc`, and `Label/ #` in a sidecar), which 3.2.2 now states; a slash inside a value is part of the value, so `Description/left / right` is valid; leading, trailing or consecutive slashes TAG_INVALID (c), and a non-`name` character TAG_INVALID (d); these replace NODE_NAME_EMPTY and the extension case of CHARACTER_INVALID.
- **Forbidden characters (2.2, CHARACTER_INVALID a).** Control characters, `[`, `]`, `~` and `"` are invalid anywhere in a HED string; the tilde was TILDES_UNSUPPORTED.
- **Case of values (3.2.3, 3.2.7.4).** The schema node names of a tag are case-insensitive in every tag form, but the value that replaces a `#` placeholder is compared exactly as written: `Label/abc` and `label/abc` are a repeated expression, `Label/abc` and `Label/ABC` are not. A tag extension and a definition name are compared like node names, without regard to case. Earlier versions did not say whether the value was included.
- **Units (3.1.4.4, 3.2.3).** Unit names, symbols and SI modifiers are case-sensitive; unit names may be pluralized, symbols never. The plural of each unit name is listed in `docs/source/_static/unit_plurals.json` (A.1.1, A.8), which validators load; no plural is derived by a rule or a pluralize function, and a unit name that the file does not list has no plural. The listed plurals are the ones that validators already accept, with two changes: the plural of `degree-Celsius` is `degrees-Celsius`, not `degree-Celsiuses`, and `uV`, a unit name of `8.3.0` and `8.4.0`, has no plural. A value with units is the number, one blank and the unit: `3ms` and `3  ms` are VALUE_INVALID. A compound unit (`m-per-s`, `m-per-s^2`) with `SIUnit` takes one SI modifier on each component, and its conversion is computed per component (UNITS_INVALID c).
- **Placeholders (Appendix B).** A `#` must be the whole value of its tag, apart from units after one blank, or the whole second part of a `Definition`, `Def` or `Def-expand` value (`Def/MyDef/#`): `Label/x#` and `Label/#x` are PLACEHOLDER_INVALID (f), which a validator may instead report as VALUE_INVALID or CHARACTER_INVALID, depending on which check finds it first.
- **Tabular files and structures (3.2.10).** A tabular file is encoded in UTF-8, and a byte-order mark at its start is not part of the first column name. A column name MUST NOT be repeated, begin or end with whitespace, or be blank (TABULAR_INVALID a, b, c); names are compared exactly as written. A value in a column with categorical or value HED annotations MUST NOT begin or end with whitespace (TABULAR_INVALID d); an empty value and `n/a` are missing values and are not checked, and the `HED` column is not subject to the rule. In a `.tsv` file a line other than the first MUST NOT be empty (TABULAR_INVALID e) and MUST have as many tab-separated cells as the first line (TABULAR_INVALID f), as BIDS also requires; a single line ending at the end of the file is allowed and a line of only tabs with the right count is a row of missing values. Every offending line is reported by its line in the file (the column-name line is line 1), and the rows are then not validated. These two rules do not apply to spreadsheets or NWB tables. A validator applies the rules of 3.2.10 to every table that carries HED annotations, whether it is stored in a file or held in a data structure in memory (a `HED` column, recognized in a `.tsv` file also when the first line is empty or the name is padded, or a sidecar with HED annotations), and MAY skip a table that carries none. Every value of a value-annotated column other than `n/a` must yield a valid HED string, even when the column is used only in curly braces (VALUE_INVALID e).
- **Timeline tables (3.2.10, 3.3).** A table is a timeline when it has an `onset` column anywhere (or the NWB `timestamp` column); 3.3.0 required `onset` to be the first column. `Onset`, `Offset`, `Inset` and `Delay` may appear only in timeline tables.
- **Sidecars (3.2.9).** A sidecar that is stored in a file is encoded in UTF-8, as BIDS requires of a JSON file. A top-level sidecar key and a categorical key under `"HED"` MUST NOT begin or end with whitespace (SIDECAR_INVALID d, e); keys match column names exactly. An annotation in a categorical entry MUST NOT be empty or blank; a column value with no annotation is given the annotation `n/a` (SIDECAR_INVALID f). A curly-brace reference to a column that has no HED annotation is SIDECAR_BRACES_INVALID, and a `{ref}` with no matching column is SIDECAR_KEY_MISSING (b). A sidecar annotation with curly braces is checked with the annotations of each referenced column substituted, one referenced column at a time, whether or not a file uses that value (3.2.9.3 rule 10); combinations of several referenced columns are not required to be checked in the sidecar and are found per row. A value column's template is substituted with its `#` unfilled, so errors that depend on its value are found per row. For the repeated-expression check only (TAG_EXPRESSION_REPEATED), the other references are removed, as for an `n/a` or blank value, and the annotation with all references removed is also checked; removal is the only substitution for `{HED}`: `(Red, {HED}), (Red)` and `(Red, {color}), (Red)` are invalid sidecar annotations. Rule 3 now removes a reference whose value is blank as well as `n/a`.
- **Schema sections (3.1, Appendix A).** Sources, Prefixes and External annotations are required in every schema (SCHEMA_SECTION_MISSING); tools always write them, empty if they have no rows. A schema without them, such as one released before `8.5.0`, can still be loaded but does not pass schema validation.
- **Changed letter meanings in Appendix B.** Validators that report letters must remap: CHARACTER_INVALID (a) is now the forbidden-character list; TAG_NAMESPACE_PREFIX_INVALID dropped its old (a), so the old (b) is now (a); SCHEMA_DEPRECATION_ERROR (h) now means a deprecated default unit (the old h duplicated f, the old i is gone); SCHEMA_DEPRECATION_ERROR (e), a deprecated property used on an attribute, is no longer used because a schema property cannot be deprecated; DEFINITION_INVALID (b) is no longer used (an empty inner group is TAG_EMPTY c); TEMPORAL_TAG_ERROR (d) is now too many inner groups in an `Onset`, `Inset` or `Offset` group (`Duration` and `Delay` are under l), and (e) is now extra top-level tags in an `Offset` group.
- **Renumbered sections.** Chapter 3 was reorganized (old 3.1.2.x is 3.1.4.x, 3.1.3 is 3.1.5, the MediaWiki and XML format sections moved to Appendix A.2 and A.3, semantic versioning moved to 1.6), Appendix A.1.4 gained two subsections (for example `#a142-conversionfactor` is now `#a143-conversionfactor`), and B.2.3-B.2.5 are now B.2.2-B.2.4. Links into the specification that use these anchors must be updated.

## New rules and features

### Reserved tags and temporal annotation

- 3.2.8 Reserved tags (formerly Special tags) names 19 reserved tags, 9 of them structural, by tag name in every schema version, and gives one table of group rules (value, anchor, other tags, minimum and maximum inner groups, timeline only, curly braces), with each column explained before the table, a paragraph on `Delay` sharing a group, and a table of the two-part values of `Definition`, `Def` and `Def-expand`. The section says why the rules are a table generated from `reserved_tags.json`; Appendix A.6 defines the file's parameters.
- No `Def` or `Def-expand` is allowed at the top level of a group whose reserved tag takes no anchor (for example `Duration` or `Delay`).
- `Definition` and `Event-context` groups may not contain a `{column}` reference; group rules are checked after the row is assembled.
- `Onset`, `Offset` and `Inset` MUST NOT occur at the same time as another `Onset`, `Offset` or `Inset` with the same anchor, and an `Offset` before its `Onset` is an error (3.2.8.3).
- The value of a `Def` or `Def-expand` is checked against the value class and units of the definition's placeholder tag, and a `Def-expand` group stands wherever its `Def` could (3.2.8.2).
- New 3.2.8.4 on `Duration` and `Delay` (units and conversion, as in the upgrade notes).
- A definition with no contents can anchor `Onset` groups whose contents vary (5.1).

### Schemas: loading, partnering and merge groups

- New 3.1.1 and 3.1.2 define version strings, namespaces and namespace prefixes (the prefix includes the colon, is chosen per dataset and is not part of a schema), partnered and unpartnered libraries, merged and unmerged files (the `unmerged` value is case-insensitive), and merge groups.
- Rules for combining schemas in a merge group (3.1.2.4, SCHEMA_LOAD_FAILED): schemas may be listed in any order; no two schemas with the same name, whatever their versions, may be in one group (SCHEMA_LOAD_FAILED c); all libraries in a group must have the same standard partner, and a standard schema listed in the group must be that partner; an unpartnered library must be alone in its namespace; a schema that cannot be found is SCHEMA_LOAD_FAILED (d).
- Identical elements shared by libraries in one merge group are compatible and kept once, carrying one `inLibrary` value per contributing library; 3.3.0 failed the load for any shared tag. Differences in prologue and epilogue are not conflicts. Chapter 7 (7.3.6) illustrates every rule with the test schemas used by hed-tests (testconflict, testclash, testminimal, testaux).
- An unmerged partnered library may not contain a tag of its partner or a Properties section; a merged library's Properties must equal its partner's (SCHEMA_LIBRARY_INVALID i, j, k). A library schema MUST NOT carry `reserved`, define a tag with a reserved name, or root a node under a reserved tag (SCHEMA_LIBRARY_INVALID l, m, n). A standard schema must define the reserved tags `reserved_tags.json` names for its version, and a reserved tag may have no child other than `#` (SCHEMA_RESERVED_INVALID).
- 3.1.3 table of version updates: the rows are in the order major, minor, patch. New rows: a listed unit removed but still derivable (patch); a tag renamed, a `#` child removed from a node, a schema attribute, value class or unit modifier removed, and `allowedCharacter` narrowed (major); a `#` child added to a node, a schema element or schema attribute deprecated, and `allowedCharacter` widened (minor). Removing a schema property is now major; it was minor, in one row with adding one.

### Schema formats and attributes (Appendix A)

- Four schema formats: MediaWiki, XML, and the new JSON (A.4) and TSV (A.5) formats.
- New schema sections Sources, Prefixes and External annotations (A.1.6-A.1.8, with subsections in each format). An empty required cell is the SCHEMA_MISSING_EXTRA warning.
- In a merged library schema, the rows that the library contributes to Sources, Prefixes and External annotations carry `inLibrary`, as its schema elements and schema attributes do (3.1.2.2; the form in each format is in A.2.5.7, A.3.5.7, A.4.5.6 and A.5.11.1). A row is identified by its key (`source`; `prefix`; `prefix` and `id`). An unmerged library schema must not have a row with the key of a row of its standard schema partner (SCHEMA_LIBRARY_INVALID h); in a merge group, rows of two libraries that are identical apart from `inLibrary` are kept once, with one `inLibrary` value per contributing library, and rows with the same key and different contents fail the load (SCHEMA_LOAD_FAILED e).
- MediaWiki format (A.2.5.7-A.2.5.9): in a row of the Sources, Prefixes or External annotations section the pairs are in a fixed order with `description` last; the value of `description` runs to the end of the row and may contain commas, and the value of any other pair MUST NOT contain one.
- TSV format (A.5.2): the header row of each of the thirteen files is the one written for standard schema `8.5.0`. A tool that writes TSV writes these header rows for a schema of any version; a tool that reads TSV also accepts the earlier header rows, listed in B.3.
- JSON format (A.4): the layout includes the top-level `units` object.
- Every section of a schema, including the prologue and epilogue, is present and may be empty; nothing is optional. The order of sections is a rule of the MediaWiki and XML formats only (3.1.4).
- An unrecognized header attribute does not prevent a schema from loading, does not affect the validation of annotations, is an error in schema validation, and is written back unchanged when a tool writes the schema (3.1.4.1); A.2.2 and A.3.2 point to that rule and no longer call it a warning. The same is stated for an undefined attribute on a schema element (3.1.4.7).
- `annotation` attribute (A.1.4.2): one grammar, `prefix:id value`, where `prefix:id` is a row of External annotations and `prefix` a row of Prefixes; a link to an external ontology term uses a SKOS mapping property (`skos:exactMatch ncit:C25499`). A `dc:source` value must name a row of Sources, by its name or by a URL under its link. A violation is the SCHEMA_ANNOTATION_INVALID warning (a-d). Applies to standard schemas >= `8.5.0`, libraries partnered with them, and unpartnered libraries.
- `hedId` (A.1.4.7): `HED_` plus seven digits, assigned only at release and never reused; retired identifiers are recorded under `retired_ids` in hed-schemas `library_data.json`.
- `isPartOf` (A.1.4.9, added in schema `8.3.0`) is documented, and every attribute in A.1.4 now has a description.
- `allowedCharacter` (A.1.4.1): a name is a row of the 2.2 table, the alias `slash`, or a single character naming itself. From standard schema `8.5.0` and in partnered libraries, the names a value class declares define its characters; older schemas use the recorded defaults.
- Value classes (A.1.3): `textClass` is the new `value-text` set from `8.5.0` and `text` before; `nameClass` drops `blank` and `period`; `numericClass` drops `caret`; `dateTimeClass` follows the BIDS Datetime format (RFC 3339 with optional offset, one to six fractional digits, hour 00-23), and the date must exist in the Gregorian calendar; `IRIClass` is removed; `posixPath` is specified as the schemas declare it (digits, letters, slash, colon), and no placeholder of a standard schema through `8.5.0` uses it.
- Schema properties use their domain and range names, with the old names listed (3.1.4.6).

### Units

- `anyUnits` (`8.5.0`, with `Quantity`): a pseudo unit class whose placeholder accepts a unit from any unit class; a listed unit wins over a derived form (`dB`); a string derived by two classes and listed by none is SCHEMA_DUPLICATE_NODE (c); `anyUnits` may list no units or `defaultUnits` (SCHEMA_ATTRIBUTE_INVALID d).
- A `#` placeholder has at most one unit class and, when it has one, `valueClass=numericClass` as its only value class; several value classes are allowed only without a unit class (SCHEMA_ATTRIBUTE_VALUE_INVALID; checked for `8.5.0`, libraries partnered with it, and unpartnered libraries).
- No unit of a class may be derivable from another unit of the class by an SI modifier (SCHEMA_DUPLICATE_NODE b, `8.5.0`, libraries partnered with it, and unpartnered libraries); `defaultUnits` may be such a derived form (`mA`, `uV`).
- `conversionFactor` (A.1.4.3) is the factor by which a value in the unit is multiplied to obtain default units; a unit without one has no defined conversion.
- The `unitPrefix` attribute and `$` are deprecated as of `8.5.0`. The A.1.1 unit table reflects `8.5.0` (25 unit classes).
- The A.1.1 table of unit plurals is generated from `docs/source/_static/unit_plurals.json`, which lists the plural of every unit name of the released schemas that has one (38 entries); validators load the file instead of deriving plurals. The plural of a unit name with an SI unit modifier is the modifier followed by the listed plural (`milliseconds`). Appendix A.8 defines the file.

### Character sets

- The 2.2 table is generated from `docs/source/_static/character_sets.json`, which gives each set as a regular expression usable from Python and JavaScript, the per-version defaults of the standard value classes, and the characters that structure a HED string; validators load the file instead of transcribing the table. Appendix A.7 defines the file and its fields.
- An element description, the prologue, and the epilogue may contain the `text` characters and the comma; 3.3.0 allowed no comma in the prologue and epilogue (2.2, 3.1.4.2, 3.1.4.9, SCHEMA_CHARACTER_INVALID d, e).
- The name of every schema element, schema attribute and schema property consists of `name` characters; the name of a unit or unit modifier may also contain the characters it declares with `allowedCharacter`, as `m^2` declares `caret` (3.1.4). SCHEMA_CHARACTER_INVALID b and c are reworded to match: b covers the schema elements other than tags, the schema attributes and the schema properties, c a blank in a unit name or symbol.
- New set `value-text`; `forward-slash` added with the alias `slash`; `name` no longer lists `period`; `nonascii` is code 160 and above.

### Tabular files and sidecars

- The column-name rules apply to spreadsheets with a header row and to NWB tables; the NWB `timestamp` column counts as `onset`, so a table with both repeats a name.
- Curly-brace notation applies to any container of named columns, including ndx-hed NWB tables.
- A value of a categorical column that has no annotation in the sidecar, and a curly-brace reference to a column that the tabular file does not have, are warnings (3.2.9.2, SIDECAR_KEY_MISSING a, b); the text no longer says a tool may choose to warn.

## Error codes (Appendix B)

Error codes are given only in Appendix B. The chapters and Appendix A state what is required or invalid and no longer name the code a tool reports; no code was added, renamed or removed by this change.

### Added

- ONSETS_UNORDERED (warning): the rows of a timeline table are not in time order.
- SCHEMA_ATTRIBUTE_INVALID (e): a schema property is used but is not defined in the properties section.
- TABULAR_INVALID (a-f): repeated, padded or blank column name; padded value in an annotated column; empty line (e); line with a different number of cells than the column-name line (f).
- SCHEMA_ANNOTATION_INVALID (warning, a-d).
- SCHEMA_MISSING_EXTRA (warning).
- SCHEMA_RESERVED_INVALID (a, b).
- Appendix B says what the star on a code means: the code is a warning, which does not make the annotation or the schema invalid and which a tool may let the user suppress; every other code is an error. SCHEMA_ANNOTATION_INVALID and SCHEMA_MISSING_EXTRA, which had the star, now also have the (WARNING) line.
- SCHEMA_LOAD_FAILED (f): a schema file that cannot be parsed in its format, when no MediaWiki or XML format code applies; no code is specific to the JSON or TSV format. B.2.4 names the four formats and no longer says that the Python exception usually carries SCHEMA_LOAD_FAILED.
- B.3 Differences for earlier schema versions: the schema-version notes are removed from the chapters and appendices, and the rules that a validator applies differently to an earlier standard schema (or a library partnered with one) are collected here. Its opening says which entries apply to an unpartnered library schema, which has no standard schema version: value class characters, the `required` attribute and the schema property names as for a standard schema < `8.3.0`; the placeholder unit class, derived unit and `annotation` form rules as for `8.5.0`.

### Removed

- NODE_NAME_EMPTY: the slash cases are TAG_INVALID (c).
- TILDES_UNSUPPORTED: the tilde is CHARACTER_INVALID (a).
- UNITS_MISSING (warning) and VERSION_DEPRECATED (warning): no replacement.
- STYLE_WARNING (warning): no replacement. The capitalization of schema nodes and of tag extensions remains a convention (3.1.5.1), and no code is reported for it.

### New or changed reasons

- CHARACTER_INVALID a; DEFINITION_INVALID b (no longer used), d, i, l; PLACEHOLDER_INVALID d, e (several `#`), f (`#` not directly after a slash); SCHEMA_CHARACTER_INVALID b, c, d, e; SCHEMA_DEPRECATION_ERROR e (no longer used), h; SCHEMA_DUPLICATE_NODE b, c; SCHEMA_LIBRARY_INVALID i-n; SCHEMA_LOAD_FAILED c, d, e; SCHEMA_SECTION_MISSING b; SIDECAR_INVALID d, e, f; SIDECAR_KEY_MISSING b; TAG_EXTENSION_INVALID b, c; TAG_GROUP_ERROR c, d, e; TAG_INVALID b, c, d; TAG_NAMESPACE_PREFIX_INVALID a; TAG_REQUIRES_CHILD b; TEMPORAL_TAG_ERROR d, e, h, k, l, m, n, o; UNITS_INVALID c; VALUE_INVALID c, e; WIKI_DELIMITERS_INVALID e (a piece of a Sources, Prefixes or External annotations row that is not a `name=value` pair).

## Clarifications

- Blanks before and after a comma or a parenthesis in a HED string are not significant (3.2.7). Earlier versions said so only in the definition of TAG_EMPTY.
- New 3.3 Annotation semantics: reversibility, grouping, event structure, row assembly, and timeline versus descriptor tables. Tags describing properties of one object SHOULD be grouped; a descriptor table may use `Event` tags but not `Onset`, `Offset`, `Inset` or `Delay`.
- The `required` schema attribute exists only in standard schemas < `8.3.0` and the unpartnered SCORE `1.0.0`, and no released schema puts it on a tag. Its rules moved from 3.2.10.3 and DEFINITION_INVALID (j) to B.3; REQUIRED_TAG_MISSING stays in Appendix B and points there.
- The short form of a tag is its last node alone; a path that starts between the root and the last node is an intermediate form (Chapter 2). All unit modifiers are case-sensitive (A.1.4.16). The tags of one merge group are the ones written without a namespace prefix (3.2.6, 6.3.5).
- Schema file formats are described only in Appendix A. The MediaWiki and XML format sections of Chapter 3 and their example schema are now in A.2.1 and A.3.1; the layout overview (3.1.4) lists the sections without markup; the rooted-node example of Chapter 7 is in A.2.4; and Chapter 8 no longer repeats a tag and an attribute in MediaWiki and XML form (its sections 8.1.4.4, 8.2.2.1, 8.2.2.2, 8.2.3.4 and 8.2.3.5 are removed and the following ones renumbered).
- The rules that a schema attribute and a property must be defined before use, which were stated only in the MediaWiki format section, are in 3.1.4.7 and 3.1.4.8.
- The rules for schema version changes are stated once, in 3.1.3 Version updates, which is normative; 1.6 Semantic versioning points to it.
- Chapter 2 adds the terms HED entity, merge group, namespace, namespace prefix, node, reserved tag, schema attribute, schema element, schema property, schema section, structural element and table, and rewrites `Event-context`.
- The terms for the parts of a schema follow the HED ontology: a schema element is a tag, unit class, unit, unit modifier or value class; schema attributes, schema properties and the structural elements (header, prologue, epilogue) are HED entities but not schema elements; the classes and properties common to all schemas are the base ontology (2.1, 8.2). A schema attribute with `elementDomain` may also be assigned to a schema attribute, a schema property carries only `hedId` and cannot be deprecated, and no schema attribute is assigned to the header (3.1.4.8). Chapter 8 is corrected against the ontology release of 2024-06-10.
- "Auxiliary sections" has one meaning, the one in Chapter 2: the sections for unit classes with their units, unit modifiers, value classes, schema attributes and schema properties. The prologue, the epilogue and the three extra sections are not auxiliary sections (7.3.3, 7.3.6, 7.4.3, A.2.3). Four headings of Appendix A are renamed to say what they contain, which changes their anchors: A.1 is "Auxiliary and extra schema sections", and A.2.5, A.3.5 and A.4.5 are "MediaWiki (XML, JSON) sections after the schema section". The merge rules for auxiliary sections (3.1.2.4) now name unit modifiers and schema attributes.
- Of the reserved tags that are not structural, 3.2.8 says that `Condition-variable` has defined behavior and points to 5.6; `Task` is no longer named there, because no section describes a behavior for it. A.1.4.12 points to 3.2.8 for this.

The links from eleven older entries to other chapters are removed: a glossary entry links only to other glossary entries. The Reserved tag entry names `reserved_tags.json` as the file that validators use, the Table entry gives the NWB `timestamp` column as an equivalent of `onset`, and the Structural element entry is rewritten.
- Chapter 6 (6.2 Table-level handling) defines a tabular file as one table with a one-line header and one or more sidecars.
- New 6.4 HED support of NWB: the four types of the ndx-hed extension (`0.3.0`), where an NWB file holds what a BIDS dataset holds in a `HED` column, a sidecar and `dataset_description.json`, the forms of the HED version in an NWB file, and pointers to the chapter 3 rules for NWB tables. Chapters 1 and 6 name NWB beside BIDS.

The identifier range table (8.3.2) adds the tag ranges of the MOUSE and SLAM library schemas. 8.3.3 states the IRI of an entity: its `hedId` appended to the undated entity prefix `http://purl.org/hed/hed/`. # Release 3.3.0 July 5, 2024

Specification 3.3.0 accompanies HED standard schema `8.3.0`. It adds Chapter 8 on the HED ontology and the `hedId` identifiers, "lazy partnering" for loading several partnered libraries together, named character sets with UTF-8 support, domain and range names for the schema properties, and deprecation. The onset errors are merged into TEMPORAL_TAG_ERROR with new rules for `Delay` and `Duration`, and tabular files whose first column is not `onset` may not use `Onset`, `Offset` or `Inset`.

## Upgrade notes for implementers

- Error codes renamed: ONSET_OFFSET_INSET_ERROR -> TEMPORAL_TAG_ERROR; TAG_PREFIX_INVALID -> TAG_NAMESPACE_PREFIX_INVALID (3.2.6 is now Tag namespace prefixes).
- Schema properties renamed (A.1.5): `boolProperty` -> `boolRange`, `elementProperty` -> `elementDomain`, `nodeProperty` -> `tagDomain`, `unitClassProperty` -> `unitClassDomain`, `unitModifierProperty` -> `unitModifierDomain`, `unitProperty` -> `unitDomain`, `valueClassProperty` -> `valueClassDomain`; `isInheritedProperty` is replaced by `annotationProperty`.
- `rooted` takes a value: `rooted=XXX` names the standard-schema node the library node goes under when merged (7.2).
- A tabular file whose first column is not `onset` may not contain `Onset`, `Offset` or `Inset` (3.2.10.1).
- `Delay` and `Duration` must each be in a top-level group with exactly one inner group, and may share it only with each other (TEMPORAL_TAG_ERROR a, b, d, l, m; TAG_GROUP_ERROR c).
- Definitions are barred from any sidecar entry that contains anything other than definitions (DEFINITION_INVALID k).
- Curly braces may not appear in the `HED` column, may not be nested, and may not substitute for a placeholder (3.2.9.3, SIDECAR_BRACES_INVALID d).
- Units are case-insensitive except unit symbols and unit modifiers (3.1.2).
- Schema versions earlier than `8.0.0` are no longer supported by validators.
- The schema attributes `required` and `recommended` are removed in schema `8.3.0`.

## New rules and features

### Character sets

- New 2.2 Character sets and restrictions: named classes (`ascii`, `nonascii`, `printable`, `text`, `name`, ...) and named single characters such as `comma` and `dollar`. UTF-8 is allowed from schema `8.3.0`. Node names and tag extensions use `name` characters; unit class and value class names too.

### Library schemas

- Lazy partnering (7.3.6, introduced with schema `8.3.0`): libraries listed without a prefix form one merge group, and libraries sharing a prefix form another; all must have the same standard partner, group prefixes must be unique, and violations are SCHEMA_LOAD_FAILED.
- New examples of unmerged and merged rooted nodes; the examples use TESTLIB `2.0.0` instead of SCORE `1.1.0`.

### Schema formats and attributes (Appendix A)

- The schema attribute table has Domain and Range columns, with subsections A.1.4.1 onwards.
- New attributes `deprecatedFrom`, `hedId`, `inLibrary`, `reserved`, `rooted`; new properties `annotationProperty`, `numericRange`, `stringRange`, `tagRange`, `unitClassRange`, `unitRange`, `valueClassRange`.
- Deprecation (A.1.4.4 `deprecatedFrom`): the value must be an earlier released version; a deprecated tag may not be a `suggestedTag` or `relatedTag`; children of a deprecated tag must also be deprecated or moved. Use of a deprecated element is the ELEMENT_DEPRECATED warning.
- Value classes: new `IRIClass`; `textClass` is `printable` or `nonascii` without curly braces; `nameClass` adds `blank`, `period` and `nonascii`; `dateTimeClass` gains a BIDS regular expression. New unit class `temperatureUnits`.
- The MediaWiki header table adds `withStandard` and `unmerged`.

### Ontology

- New Chapter 8, The HED ontology: annotator and ontologist views and the HED information space (8.1); the schema-to-OWL mapping (8.2); global identifiers `HED_xxxxxxx`, their ranges, and their IRIs (8.3).

### Tabular files

- New 3.2.10.1 Tabular types: a file whose first column is `onset` is a timeline. 6.3.1 adds a table of BIDS tabular file types; HED is not supported in BIDS timeseries files (6.3.2).

## Error codes (Appendix B)

### Added

- ELEMENT_DEPRECATED (warning), SCHEMA_LOAD_FAILED, SCHEMA_ATTRIBUTE_VALUE_INVALID, SCHEMA_DEPRECATION_ERROR; TEMPORAL_TAG_ERROR and TAG_NAMESPACE_PREFIX_INVALID by renaming.

### Removed

### Changed reasons

# Release 3.2.0 May 12, 2023

Specification 3.2.0 introduces the `Inset` tag for intermediate points of events of temporal extent, partnered library schemas (merged and unmerged, with the `withStandard` and `unmerged` header attributes and the `rooted` and `inLibrary` attributes), and curly-brace column references in sidecars.

## Upgrade notes for implementers

- Error codes renamed or merged: ONSET_OFFSET_ERROR -> ONSET_OFFSET_INSET_ERROR; LIBRARY_NAME_INVALID -> SCHEMA_LIBRARY_INVALID (a).
- DEFINITION_INVALID gains a new (e), definitions may not use curly braces, so the old e-j are now f-k.
- CHARACTER_INVALID (b) now means curly braces in a HED string that is not in a sidecar. Its old meaning, a value not allowed by its value class, duplicated VALUE_INVALID (b), which remains.

## New rules and features

### Temporal annotation

- `Inset` (3.2.8.3, 5.3.2) marks an intermediate point of an ongoing event: it is anchored by the `Def` or `Def-expand` of an ongoing `Onset`, takes at most one additional tag group, and a `Def/xxx/#` value must match the `Onset`'s. `Def-expand` groups may also anchor `Onset` and `Offset` (5.3.1).

### Sidecars

- New 3.2.9.3 Sidecar curly braces: the name in braces is `HED` or a HED-annotated column; the column's annotation replaces the braces; when the value is `n/a` the reference and its extra parentheses and commas are removed; a column may not both be referenced and use braces itself; no braces inside `Definition`.

### Library schemas

- New 7.2 Partnered schemas: merged and unmerged files and their names (`HED_score_1.1.0_unmerged.mediawiki`); an unmerged file has `unmerged="true"` in its header, only the auxiliary sections it extends, `rooted` nodes at the top level, and no `inLibrary`; a merged library's nodes carry `inLibrary`. A partnered library's terms must not overlap the standard schema. 7.3 separates general, standalone and partnered design rules; 7.3.4 covers schema namespaces.

## Error codes (Appendix B)

### Added

- SIDECAR_BRACES_INVALID (a-c); SCHEMA_LIBRARY_INVALID (a-h: library name, `withStandard` without `library`, invalid `withStandard` version, `rooted` outside an unmerged partnered library, `rooted` node not at the top level or not in the partner, `inLibrary` in an unmerged schema, unmerged schema duplicating the partner's auxiliary items); ONSET_OFFSET_INSET_ERROR by renaming.

### Removed

- ONSET_OFFSET_ERROR (renamed), LIBRARY_NAME_INVALID (now SCHEMA_LIBRARY_INVALID a).

### Changed reasons

- ONSET_OFFSET_INSET_ERROR i (same anchor at the same time for any of `Onset`, `Inset`, `Offset`), j (`Inset` without the anchor of an ongoing `Onset`), k (more than one additional group); DEFINITION_INVALID e; CHARACTER_INVALID b.

## Document and repository

- The repository adds schema `8.2.0` (`hedxml/HED8.2.0.xml`, `hedwiki/HED8.2.0.mediawiki`), `hedspec/HEDSpecification_3_2_0.pdf`, and test files for the new codes; the README gains the Zenodo DOI.

# Release 3.1.0 April 5, 2023

Specification 3.1.0 reorganizes the document around a new Chapter 3, HED formats, whose section 3.2 states each annotation rule and links it to an Appendix B error code. Every error code lost its `HED_` prefix and got its own linkable section. Although presented as a clarification, the release tightens several rules: definitions must have contents and may appear only in sidecar definition entries, `Def-expand` needs an inner group, `Onset` and `Offset` groups have a fixed form, and units are separated from values by exactly one blank. A set of JSON test files keyed to the error codes was added for the Python and JavaScript validators.

## Upgrade notes for implementers

- A definition must have a non-empty inner group (3.2.8.1, DEFINITION_INVALID b); 3.0.0 allowed an anchor-only definition.
- Definitions may appear only in sidecar entries that hold definitions, or in external definition lists, not in the `HED` column or in column annotations (3.2.9.1, 3.2.10.1, 5.1, DEFINITION_INVALID j); 3.0.0 allowed them anywhere.
- `Def-expand` is written `(Def-expand/xxx, (contents))` with an inner group (5.2.2, DEF_EXPAND_INVALID e, f).
- `Onset` and `Offset` groups (3.2.8.3, ONSET_OFFSET_ERROR c, e, h, i): exactly one `Def` or `Def-expand` anchor; `Onset` may add at most one inner group, and its other tags must be inside it; `Offset` contains only the anchor; the same anchor may not appear twice in one event marker.
- Units are separated from values by a single blank, prefix or suffix (VALUE_INVALID d); 3.0.0 said at least one blank.
- A placeholder with no `valueClass` is treated as `textClass` (3.0.0: `nameClass`).
- Definition names and values substituted for `#` may be schema node names.
- Sidecars (3.2.9.1): no annotation for `n/a`, and `"HED"` only as a second-level key (SIDECAR_INVALID).
- Tags are case-insensitive except units, which keep their case, and unit modifiers, which are case-sensitive (3.2.3).
- Library prefixes must be alphabetic (3.0.0: alphanumeric); an invalid prefix in the version specification is a schema loading error; at most one schema in the version list may be unprefixed (Chapter 7).
- Error codes renamed (all lost the `HED_` prefix): HED_DEF_UNMATCHED and HED_DEF_VALUE_INVALID -> DEF_INVALID; HED_LIBRARY_UNMATCHED -> TAG_PREFIX_INVALID; HED_TAG_REPEATED -> TAG_EXPRESSION_REPEATED; HED_UNITS_DEFAULT_USED -> UNITS_MISSING; HED_SCHEMA_REQUIRED_SECTION_MISSING -> SCHEMA_SECTION_MISSING.

## New rules and features

- The 5.3 table places `Duration`, `Delay`, `Inset` and `Event-context` in top-level groups and gives the forms `(Duration/x, (group))` and `(Delay/x, (group))`, noted as not fully supported until schema `8.2.0`.
- Tools must state whether they support temporal scope and the expansion of `Delay` and `Duration` (6.2).
- A library schema should not duplicate tags of the standard schema (3.0.0 allowed identical terms), and tools must handle several schemas, including a prefixed standard schema (`["st:8.1.0", "score_1.0.0"]`, 6.3.4).

## Error codes (Appendix B)

- Every code has its own section with lettered reasons, so validators can link to it.
- Added: SIDECAR_INVALID; TAG_EXTENSION_INVALID (split from HED_TAG_INVALID); LIBRARY_NAME_INVALID.
- Removed: HED_VERSION_WARNING, HED_SCHEMA_NODE_NAME_INVALID, HED_SCHEMA_LOAD_FAILED.

## Schema formats (Appendix A)

- Reorganized into A.1 auxiliary sections, A.2 MediaWiki and A.3 XML, each with prologue and epilogue subsections.
- `conversionFactor` (added in schema `8.1.0`) and `unitProperty` are listed; `nameClass` is alphanumeric plus `-` and `_`; commas and single quotes are allowed in the prologue, epilogue and descriptions; `allowedCharacter` group names `letters`, `blank`, `digits`, `alphanumeric`.
- Official schemas come from the hed-schemas repository.

## Clarifications

- New 3.1 rules for schemas: section order, header and library names, characters of the prologue and epilogue, the is-a requirement and unique node names. New 3.2.5 lists five requirements for tag extensions, 3.2.7 covers tag groups, empty groups and repeated expressions, and 3.2.10 covers row assembly and the `required` and `unique` checks.
- The temporal scope of an event includes its start sample and excludes its end sample (Chapter 2).
- Chapter 1: HED-1G is versions < `4.0.0` and HED-2G is `4.0.0` to `7.x.x`.

# Release 3.0.0 October 27, 2022

The first separately versioned HED specification. In October 2022 the versions of the HED specification and of the HED schemas were separated: the specification starts at 3.0.0 for HED-3G and applies to standard schema versions >= `8.0.0`, and the official home of the standard schemas became the hed-schemas repository. The text continues the specification that accompanied schema `8.0.0`.
